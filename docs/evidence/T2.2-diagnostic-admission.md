# T2.2 diagnostic admission evidence

T2.2 supplies the optional local backend runner used by T2.3. T1 observation and T2.1 deterministic checks operate independently of it. A failed admission returns a status and no backend output. There is no resident inference service.

## Policy and containment

- The protected workload gets the configured memory reserve on the host and at every visible, finite ancestor limit. Admission also reserves the full diagnostic leaf `memory.max`, checks both `memory.high` and `memory.max`, and requires a measured backend peak that fits the leaf's headroom. During the run, current leaf charges reduce the remaining growth budget. The runner reads live data approximately every 100 ms and stops if measurement fails, remaining reserve is threatened, or host PSI crosses 1% memory stall or 10% CPU stall on the 10-second window.
- The job cgroup must have a finite memory cap, zero swap, a finite CPU quota of at most one core, and a PID limit of 1–64. Use a smaller CPU cap and PID budget when the target workload requires it. The time budget is 1–300,000 ms. Total stdout and stderr are limited to a configured 1–65,536 bytes. The explanation adapter supplies the token cap. Only successful stdout reaches the parser.
- The forked child waits on a private socket while the broker attaches its PID to the dedicated leaf. The broker releases the child only after attachment succeeds. The child starts a separate session and applies Landlock ABI 3 filesystem mutation restrictions and `no_new_privs`, closes inherited descriptors, and applies a seccomp filter before direct exec with a fixed environment. The filter permits read-only opens and blocks socket creation, `clone3`, and alternate paths to writable or imported descriptors. It also blocks signal sends, async signal ownership changes, ptrace, cross-process memory access, and changing the parent-death signal. It covers x86_64 and aarch64. The operator supplies a trusted preinstalled adapter that honors the local, offline backend contract and runs under a dedicated account. Standard worker thread creation and joining work in the fixture. A backend that relies on signal-based thread operations such as `pthread_kill` falls outside this adapter contract.
- A nonblocking lock on the true cgroup filesystem root serializes live brokers. If the leaf remains populated at cleanup, the broker writes to the dedicated leaf's `cgroup.kill` and checks the reaped leader and `cgroup.events` for up to two seconds after the write. An unconfirmed kill returns `cleanup_failed`. Exit zero with surviving descendants is a backend failure. The leaf covers descendants that leave the original process group.
- If the broker is killed abruptly, its direct child receives the parent-death signal. Any remaining descendants keep the configured leaf populated and block the next request. A broker can also return `cleanup_failed` when a task remains stuck in the kernel. The operator must inspect the dedicated leaf and verify that it contains only the configured diagnostic workload before deliberately draining it through that leaf's `cgroup.kill`. Wait for `populated 0` before retrying. Use one fixed diagnostic leaf per host so orphan checks always inspect the prior job's leaf.

## Deployment prerequisites

Use a host-native Linux cgroup v2 root mounted at `/sys/fs/cgroup`, with memory, CPU and PID controllers, readable host PSI, Landlock ABI 3 or newer, seccomp filters and `cgroup.kill`. Broker invocations run under a dedicated unprivileged account. A host administrator provisions an empty domain cgroup exclusively for diagnostics and a sibling broker cgroup under the same parent. Keep the delegated leaf out of the monitoring and primary workload cgroups. The administrator maintains the hard limits and ensures the account can write only the common ancestor and destination `cgroup.procs` files required for attachment and the diagnostic leaf's `cgroup.kill` for cleanup. The protected workload's cgroups and hard-limit files remain administrator controlled. The runner refuses unsupported or incomplete hierarchies.

Use [the T2.3 operator guide](../operations/grounded-explanations.md) for the explanation command and trusted policy. The [disposable native smoke script](../../deploy/diagnostic/smoke-admission.sh) shows the fixture provisioning and checks. Run it only in an authorized disposable Linux host with Zig 0.15.2 and the standard `flock`, `setpriv` and `setsid` utilities.

## Provenance

TUMe's inherited NanoClaw-Next scheduler and memory probe came from the split at `fe65c25e37dab1e1c572aabde08a56467008b952`. The product runner uses a separate admission path. It reuses T1's strict `/proc/meminfo` parser and boot clock. The inherited model-selection heuristics, best-effort defaults, benchmark thresholds and subprocess runner are outside this path. The estimate input is a deployment measurement for the selected backend and model, in bytes. No research estimate serves as product acceptance. See the [repository provenance](../PROVENANCE.md) and [kernel cgroup v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html).

## Validation boundaries

Portable fixtures cover missing or malformed measurements, host and ancestor reserve, pressure changes, cancellation, deadline, the shared capture cap and unconfirmed cleanup. Linux binaries for the smoke harness build for x86_64 and aarch64. The disposable native fixture passed on an ARM64 Ubuntu 24.04 VM running kernel `6.8.0-147-generic`. It verified the shared lock, successful capture, denied access to a writable cgroup control file, blocked socket and `clone3` calls, a separate session, denied same-UID signal permission without signal delivery, denied async signal ownership and parent-death-signal changes, backend thread creation and joining, overflow, timeout, external cancellation, cleanup of a descendant in a separate session, successful reuse after cleanup, and measured-peak refusal. Every case confirmed an empty leaf. It ran without a model or a stress workload.

An early native run reproduced a kernel bug in which `clone3(CLONE_INTO_CGROUP)` delivered SIGKILL to a fresh child after `cgroup.kill`. Cgroup memory and PID event counters were zero. Gated attachment keeps the backend blocked until cgroup placement succeeds and the smoke script now checks repeated runs after a kill. See the [upstream kernel patch](https://lists.openwall.net/linux-kernel/2026/08/28/1928).

Whole-device acceptance requires an authorized physical-device workload trial. Record idle, startup, active and aborted diagnostic CPU and memory for the host and cgroup, broker delivery latency/loss, stall pressure, cleanup latency and diagnostic quality alongside resource refusals. A smoke run cannot establish those results.
